# Security Policy

## Supported versions

herdr-customize is pre-1.0: a fix lands on `main` and ships in the next
release rather than as a patch to an older tag. Only the newest release is
supported.

## Reporting a vulnerability

Report it privately through
[GitHub's vulnerability reporting](https://github.com/wapenshaw/herdr-customize/security/advisories/new).
Do not open a public issue for anything exploitable; an issue is the right
place once a fix is out.

Include what makes it reproducible:

- the plugin version (from `herdr plugin list`), your Herdr version and your
  OS;
- what an attacker controls (a theme file, a plugin's manifest or config, a
  marketplace search result, a release download) and what that gets them;
- the shortest sequence that shows it.

This is a one-person project, so a fix takes as long as it takes, but you will
hear where it stands. Say whether you plan to disclose it and when, and the
release is timed to that.
